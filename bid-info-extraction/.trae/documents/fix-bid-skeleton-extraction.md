# 修复计划：bid-skeleton-extraction Skill 优化

## 摘要

修复 `bid-skeleton-extraction` Skill 的根本性设计错误：**标书骨架应基于招标文件中的“响应文件格式”章节生成，而非提取整个招标文件的目录结构**。同时修复上一轮发现的占位符错误、增强内容位置错乱、去重不彻底等问题。

## 当前状态分析

### 核心错误
1. **骨架来源错误**：当前步骤3提取了整个招标文件的章节结构（邀请书、须知、合同草案等），而这些是**采购人**写的内容，不是供应商要填写的**标书模板**。
2. **正确来源**：标书骨架应基于招标文件中的**“响应文件格式”**（通常为最后一章）生成。该章节包含了供应商需要填写的响应函、报价表、商务资料、响应方案等模板。

### 次要问题
1. **占位符错误**：封面 `PROJECT_NAME` 应为 `SUPPLIER_NAME`；`{{填写说明}}` 不是标准占位符。
2. **增强内容位置错乱**：资质、评分、技术响应内容被追加到第五章末尾，而非插入到对应位置。
3. **去重不彻底**：增强内容与原始骨架存在重复。
4. **大量空行**：封面和第一章有大量空段落，影响生成的 Word 文档质量。

## 修改方案

### 1. 修改 SKILL.md 步骤3：提取响应文件模板

**目标**：明确骨架来源为“响应文件格式”章节。

**修改内容**：
- **3.1 识别目标章节**：
  - 使用 LLM 识别 `elements` 中标题包含“响应文件格式”、“投标文件格式”或“投标文件组成”的章节。
  - 该章节通常位于文件末尾（最后一章）。
- **3.2 提取子章节结构**：
  - 在目标章节内，按 `heading_level=2` 或 `heading_level=3` 切分子章节（如“1.响应函”、“2.授权委托书”、“3.报价表”等）。
  - 过滤掉非模板内容（如通用的编制说明、装订要求等），保留具体的格式模板。
- **3.3 构建骨架**：
  - 将封面 + 各子章节模板组装成 `skeleton.json`。
  - 每个子章节作为一个 `chapter`。

### 2. 修改 SKILL.md 步骤4：骨架完善（增强）

**目标**：将资质、评分、技术要求**合并**到对应的模板章节中，而非追加到末尾。

**修改内容**：
- **4.1 合并策略**：
  - **资质要求**（`qualifications`）：合并到“商务资料”章节。
  - **评分标准**（`evaluationCriteria`）：合并到“响应方案”章节。
  - **技术需求**（`technicalRequirements`）：合并到“响应方案”章节。
  - **合同条款**（`contractTerms`）：通常不合并到骨架（除非招标文件要求提供合同条款响应表）。
- **4.2 定位目标章节**：
  - 通过章节标题关键词（如“商务资料”、“响应方案”）定位要插入的位置。
- **4.3 插入内容**：
  - 在目标章节的 `elements` 列表中，找到合适的位置（通常是章节末尾或特定段落后）插入新元素。
  - 使用 `list.insert(index, element)` 而非 `list.append()`。

### 3. 修复占位符逻辑

**修改内容**：
- **封面替换规则**：
  - 首行（供应商名称） → `{{SUPPLIER_NAME}}`（而非 `PROJECT_NAME`）。
  - 项目名称 → `{{PROJECT_NAME}}`。
  - 采购编号 → `{{PROJECT_NO}}`。
  - 采购人 → `{{BUYER_NAME}}`。
- **填写说明处理**：
  - 将“填写说明”类文本替换为具体的占位符说明，或保留为普通文本，避免生成 `{{填写说明}}` 这样的无效占位符。

### 4. 优化去重逻辑

**修改内容**：
- 在增强阶段（步骤4），新增内容前必须与骨架中已有内容进行比对。
- 使用**模糊匹配**（如去除标点、空格后比较）和**子串匹配**（检查是否已包含核心信息）。
- 去重日志应记录跳过的原因（如“已存在于5.2节”）。

### 5. 清理空行

**修改内容**：
- 在步骤3提取骨架后，遍历 `elements`，移除连续的空段落（`text=""`）。
- 保留必要的分隔段落（如章节间的空行），但移除多余的空行。

## 验证步骤

1. **结构验证**：生成的 `skeleton.json` 的章节结构应为：封面、响应函、授权委托书、保证金、报价表、商务资料、响应方案。
2. **内容验证**：检查“商务资料”章节是否包含资质要求，“响应方案”章节是否包含评分和技术要求。
3. **占位符验证**：检查封面的 `{{SUPPLIER_NAME}}` 和 `{{PROJECT_NAME}}` 是否正确。
4. **Word 模板验证**：生成的 `template.docx` 应无多余空行，且内容符合标书要求。
